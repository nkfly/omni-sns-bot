# Changelog

## Unreleased

- **Reduce first-run friction without broadening send permission.** A first-run exercise exposed repeated/number-misaligned questions, unanswered-vs-none ambiguity, browser access discovered only after repeated requests to paste posts, and connection needed before voice extraction. Add a setup conversation contract, a private progress template, bounded existing-session Chrome reads, separate managed/reference identities, explicit partial-corpus reporting, scoped style/template/public-action decisions, and a setup-only finish. Real account material remains private; only synthetic regression cases are contributed.
- **Preserve the editor's cadence rather than coercing it into defaults.** A weekly minimum was easily mistaken for the legacy weekly ceiling, no personal reply cap had no documented representation, an explicitly empty excluded-topic list failed strict validation, and an evening ending at midnight was ambiguous. Add optional `min_posts_per_week`, confirmed-empty topics, nullable editor reply caps, and next-day `00:00` windows. Validate numeric caps, feasible minima, window types/times and browser opt-in; keep existing non-empty exclusions and weekly-ceiling workspaces compatible. Browser/platform ceilings still apply separately.
- **Give raw HTTP and browser publishing the same duplicate stop as the helper.** Assistants that do not run `publish_text.py` only had a sentence telling them to "persist intent", so a timeout or an unseen click could be treated as failure and sent again. A second create or Post click can publish the same caption twice. Require a workspace intent file before the request or click, verify the caption on the profile afterward, and refuse another attempt until that check shows it is absent and the editor authorizes a retry. The helper's own journal is unchanged.
- **Make the Threads helpers usable on Windows.** `os.fchmod` is missing on Windows before Python 3.13, `stat.S_IMODE` does not come back as `600`, so every token read was rejected, and opening a directory to fsync fails. A Windows editor could not exchange or refresh a token with the stdlib helpers. Keep the POSIX mode and owner checks on macOS and Linux. On Windows, skip those checks and the directory fsync, still refuse a path inside a git repo, document `%APPDATA%` plus hidden `Read-Host -AsSecureString` entry (no literal secret in history), and note that Credential Manager is not read by the scripts. Tests cover the non-POSIX branch on every OS and the strict mode checks where Unix modes exist.
- **Keep a memory card pasteable, and name where the workspace lives.** A card that kept every caption forever outgrows a conversation, and there was no field for a future store, so a Google Drive sync would have needed a second loop. After a post is confirmed published, items older than the five most recent keep only id, permalink, and date. Pending and unconfirmed items keep the full caption. Add `storage` (`local_files`, `memory_card`, `external`) and put external connectors such as Google Drive on the roadmap. `external` still uses the same files; the loop does not call Drive.
- **Run the offline suite on the three desktop OSes.** The new Windows branch and the workspace checks were only exercised on the author's platform, so a mode-bit or path mistake could ship. Add a GitHub Actions workflow that runs helper self-tests, workspace and template checks, and the unittest suite on `ubuntu-latest`, `macos-latest`, and `windows-latest` for Python 3.10 and 3.12. The suite stays offline and uses dummy credentials.
- **Let the editor auto-send a narrow class of FAQ replies before ten posts.** The first-ten rule forced `always_ask` for replies as well as posts, so a question about opening hours waited even after the editor asked for those answers to go out. Posts still wait for the first ten editor-approved publications. A new policy flag, default `false`, may policy-approve a reply before that count only when the editor explicitly enables it (and that request is logged), triage is `answer_from_faq`, the FAQ source is `editor`, sensitivity and risk are `low`, and safety holds, quotas, and the other `always_ask_even_on_full_auto` reasons still apply. `imported` answers do not qualify.

- **Preserve OAuth tokens when parsing successful responses.** Redacting the raw response before parsing could turn a refreshed token into the literal `[redacted]` when the API returned the input token, then overwrite the usable credential while reporting success. Preserve successful response data and redact errors at output boundaries instead. The regression covers both unchanged and rotated tokens without printing either.
- **Save publish intent and container ids before proceeding.** A timeout or interrupted process does not prove a post failed. The old helper retained the container id only in memory, and the loop allowed an immediate retry, which could create a duplicate post. Require a durable per-item attempt journal, refuse another create with the same journal, and provide read-only recovery. An unknown outcome remains `publishing` until reconciled; a new attempt requires confirmation that the previous one did not publish and editor authorization.
- **Complete automatic approval transitions.** The status table told every `pending_approval` item to wait, even when the selected policy allowed automatic approval. Define when a later loop evaluates the policy, records its decision and advances the item to `approved`, so eligible drafts can progress without the assistant inventing a missing step.
- **Keep literal secrets out of shell history.** The previous examples used `export THREADS_APP_SECRET="..."` and `export THREADS_CODE="..."`; replacing the placeholders with real values would record them in an interactive shell's history. Use hidden input with command tracing off, export variable names only, and unset the temporary secrets after exchange. Read the token file directly for later commands so a shell environment does not retain a stale token after refresh.
- **Protect token files before exposing new contents.** Opening an existing file with mode `600` does not tighten its existing permissions, so writing before `chmod` could expose the new token through a mode-644 file. Write and flush a private mode-600 temporary file, then atomically replace the destination; failed replacement preserves the previous token. Both helpers also reject token-file reads with unsafe permissions or a different owner.
- **Check the quotas required by the action and fail closed.** The publisher fetched reply usage but only checked the post quota, permitting a reply attempt after its quota was exhausted. It also treated missing fields as unused capacity. Reply attempts now require valid post and reply quotas; missing, malformed or exhausted required values block container creation. Ordinary post checks do not request reply-only fields, avoiding unnecessary permission requirements.
- **Represent an unresolved AI-label choice explicitly.** The template's `disclose_ai: false` made an unanswered per-item question look like a deliberate refusal to label. Start at `null`, require the editor's explicit true/false choice under `editor_decides`, and validate queued publication decisions against the policy. Historical publications keep their recorded decisions rather than being rewritten to match today's policy.
- **Make the no-files fallback usable across conversations.** The old operating loop required YAML files even after setup selected a memory card, and the card stored only upcoming ids. Route assistants without persistent files to a manual `draft_only`, `always_ask` loop, preserving full pending captions, decisions and publication confirmations. This prevents repeated setup and avoids reconstructing or reposting an approved caption from an id alone.
- **Use one approval definition and keep practice out of publication.** Different files described the first ten posts as either manually approved or eligible for `auto_low_risk`, leaving assistants to choose between conflicting rules. Make the operating loop authoritative: the first ten actually published, editor-approved posts require `always_ask`, and loosening still needs an explicit request. Practice items never publish, even if their wording is approved; approving a style sample must not accidentally schedule it.
- **Test the failure paths as well as the happy path.** Existing self-tests and example validation passed despite the issues above. Add 28 offline regression tests for credential preservation and privacy, quota rejection, interruption/recovery, duplicate prevention and workspace publication gates; extend both helper self-tests with regressions. Tests use dummy credentials and temporary files, with no live OAuth or publishing. Both helper self-tests, the full regression suite, example/template validation and `git diff --check` passed for this change.

## 0.1.0 — 2026-11-02

- Bot entry point (`BOT_START_HERE.md`, `AGENTS.md`) and an operating loop that works for assistants with or without files, HTTP, a browser, or a scheduler.
- Account profile interview, voice extraction and presets, anti-AI writing guide (English, Traditional Chinese, Japanese), and a pre-draft self-check.
- Threads adapter: official API runbook checked against Meta's docs on 2026-11-02, browser fallback, quotas, approval levels, calendar, FAQ triage.
- Placeholder adapters for Reddit, Instagram, Facebook, and X, plus a guide for adding a platform.
- Fictional worked example (`examples/salty-pages`).
- Optional standard-library helpers to exchange a Threads token and publish a text post, without taking secrets on the command line.
